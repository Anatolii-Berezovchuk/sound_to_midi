## Предлагаемая будущая структура

Это набросок, а не уже созданные файлы. Добавляем каждый элемент только тогда, когда он нужен.

```text
проект/
├── README.md
├── .gitignore              — исключения для Git
├── requirements.txt        — выбранные зависимости Python
├── docs/
│   └── plan.md
├── src/
│   ├── main.py             — запуск локального эксперимента
│   ├── audio.py            — чтение и подготовка аудио
│   ├── transcription.py    — вызов готовой модели, получение нот/MIDI
│   └── notation.py         — подготовка нотной записи и экспорта
├── data/
│   └── input/              — локальные тестовые аудиофайлы
├── output/                 — локальные результаты обработки
└── models/                 — скачанные модели, если потребуются
```

Аудиофайлы, результаты, веса моделей, виртуальное окружение и секреты не отправляем в GitHub. Для них подготовлен `.gitignore`.

## Последовательность

1. Согласовать структуру и выбрать приватный репозиторий GitHub. Подключить локальную папку и отправить документацию.
2. После разрешения пользователя настроить Python и отдельное виртуальное окружение. Выбрать первую готовую модель с учётом совместимости.
3. После отдельного разрешения написать минимальный эксперимент: один короткий файл → MIDI. Проверить результат на слух и измерить время обработки.
4. После оценки MIDI добавить нотную запись. Проверить ритм, длительности, читаемость и распределение между руками. PDF не гарантирует правильность распознавания.
5. Собрать удобный локальный запуск.
6. Подключить Telegram-бота для личного использования. Затем рассмотреть Mini App.

## Как данные будут проходить через программу

Аудиофайл → подготовка звука → готовая модель → ноты со временем начала и длительностью → MIDI → обработка ритма и нотная запись → MusicXML/PDF.

MIDI позволяет послушать распознанные ноты. MusicXML нужен для редактирования нотной записи. PDF нужен для чтения и печати.
