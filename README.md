# sound_to_midi

Музыка → ноты для фортепиано.

Личный экспериментальный проект. В перспективе: загрузка аудио через Telegram и получение нот для фортепиано.

## Первая пробная версия

Короткий фрагмент сольного фортепиано (20–30 секунд) обрабатывается на ПК готовой моделью. Результат — черновой MIDI, затем нотная запись. Качество и скорость проверяем экспериментально; распознавание любых песен пока не является требованием.

## Где работаем

- Редактор: VS Code.
- Рабочая папка: `C:\проект`.
- Язык обработки аудио: Python 3.11.9. Отдельное окружение: `.venv`.
- Git хранит историю изменений локально; GitHub будет хранить удалённую копию проекта.
- Обработка запускается на ПК. Telegram подключаем после локального прототипа.

## Правило работы

Двигаемся небольшими шагами. Перед написанием или изменением кода приложения запрашиваем разрешение пользователя на конкретный шаг. Документация и план не означают разрешения писать приложение. Не генерируем всё приложение сразу.

## Текущее состояние

Созданы документация, исключения для Git, `requirements.txt`, скрипт распознавания `src/main.py` и отдельный эксперимент с ритмом `src/quantize.py`.

Для первого эксперимента выбран Basic Pitch 0.4.0 — готовая модель Spotify для преобразования аудио в MIDI. Установка зависимостей: `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`. Успешную установку и загрузку модели проверяем отдельно; качество распознавания ещё не оценено.

Проверка окружения выполнена: зависимости установлены без конфликтов (`pip check`), модель успешно загружается через TensorFlow 2.15.0. Текущая установка работает на CPU: TensorFlow не обнаружил GPU.

## Первый запуск

В терминале VS Code из папки проекта:

```powershell
.\.venv\Scripts\python.exe src\main.py data\input\fur_elise.ogg
```

По умолчанию обрабатываются первые 25 секунд. Можно выбрать другой отрывок:

```powershell
.\.venv\Scripts\python.exe src\main.py "data\input\my_recording.wav" --start 10 --duration 20
```

Длительность ограничена 30 секундами. Для короткой записи обрабатывается доступный остаток. Время в результатах отсчитывается от начала выбранного отрывка. Повторный запуск не перезаписывает результаты: выбери другую папку через `--output-dir output\second_try`.

В `output/` сохраняются:

- `*_source.wav` — исходный отрывок в моно для сравнения;
- `*.mid` — распознанные ноты для прослушивания или импорта в нотный редактор;
- `*_notes.csv` — начало, конец, длительность, номер MIDI, название ноты и сила нажатия.

Обозначения нот в CSV используют стандарт MIDI: C4 — среднее до (MIDI 60). Предполагаемый темп исходного MIDI — стандартное значение библиотеки (120), а не определённый темп исполнения. `main.py` не округляет ритм. Руки не разделяются, PDF пока не создаётся.

Пробный запуск на первых 25 секундах «К Элизе» завершился: 141 распознанная нота, 13,7 с на чтение, распознавание и сохранение после загрузки библиотек. Это техническая проверка, а не оценка музыкальной точности. Источник: [описание тестовой записи](docs/test-audio.md).

Локальная папка подключена к репозиторию https://github.com/Anatolii-Berezovchuk/sound_to_midi, ветка `main`.

Подробности: [план и структура](docs/plan.md).

## Пробное выравнивание ритма

Пользователь прослушал исходный MIDI в MuseScore: мелодия в целом узнаваема, нотная запись грязная, паузы и длительности странные. Следующий эксперимент меняет только время начала и окончания нот.

```powershell
.\.venv\Scripts\python.exe src\quantize.py output\fur_elise_0s_25s.mid --bpm 120 --meter 3/8
```

Новый файл: `output/fur_elise_0s_25s_quantized_120bpm_d4.mid`. Исходный MIDI сохраняется. Если результат уже существует, открой его либо задай другое имя через `--output output\rhythm_test2.mid`.

120 BPM здесь — пробный темп **в четвертях в минуту**, а не измеренный темп записи. Размер 3/8 задаётся явно для этого произведения; сам скрипт использует 4/4, если `--meter` пропущен. Обозначение Poco moto не задаёт точное значение BPM.

По умолчанию сетка — шестнадцатые (`--division 4`), при 120 BPM шаг равен 0,125 с. Начала и окончания округляются к ближайшим узлам сетки от нулевой секунды; минимальная длительность — один шаг. Пауза перед музыкой не удаляется. Список высот нот и сила нажатия сохраняются. Переменный темп исходного MIDI заменяется одним заданным темпом; педальные события и другие контроллеры остаются на исходных временах.

Это простой тест постоянной сетки: он не учитывает рубато, триоли, затакт и положение первой доли. При неверно выбранном темпе ритм может стать хуже. Длительности после округления могут по-прежнему потребовать лиг в нотном редакторе. Лишние и пропущенные ноты, октавы и разделение рук не исправляются.

Проверка на текущем отрывке: MIDI после сохранения читается, все 141 нота и их сила нажатия сохранены, начала и окончания находятся на сетке, длительности положительны. Музыкальную оценку выполняет пользователь сравнением с исходником.
